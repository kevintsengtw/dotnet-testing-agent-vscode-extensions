# dotnet Testing Agent v0.8.3 安裝指南

此版新增 Code Coverage 面板，供使用者選擇方案、測試專案與平台，複製覆蓋率及 HTML 報告指令；Claude／Codex 模式面板另新增預設測試工作流程提示詞的查看與複製。兩項功能均可在尚未初始化工作流程時使用。

## 內建離線版本

| 內容 | 來源版本 |
| --- | --- |
| Shared Skills | `v2.4.5` |
| unit-test-scenarios | `d0050198` 精確 commit |
| Claude Full | `v1.7.3` |
| Claude Lite | `v1.2.0` |
| Codex Full | `v1.3.1` |
| Codex Lite | `v1.2.2` |

內建來源沿用 v0.8.2，工作流程模式的安裝、升級與檔案保護維持既有行為。

## 前置需求

- VS Code 1.85 以上、Node.js 18 以上。測試指令需已安裝適用的 .NET SDK；`.slnx` 需 .NET SDK 9.0.200 以上（[官方說明](https://devblogs.microsoft.com/dotnet/introducing-slnx-support-dotnet-cli/)）。
- VSTest：相容的 `Microsoft.NET.Test.Sdk`、測試介面卡及 `coverlet.collector`。
- MTP 原生：.NET 10 SDK 以上、MTP 1.7 以上、MTP runner 與相容的 `Microsoft.Testing.Extensions.CodeCoverage`。
- MTP 舊版相容：相容的 MTP／SDK、`Microsoft.Testing.Platform.MSBuild`、已啟用 `TestingPlatformDotnetTestSupport` 與 CodeCoverage 擴充套件；.NET 10＋MTP 2 不支援此模式。
- HTML 報告：終端機可直接呼叫的 ReportGenerator 全域工具（`dotnet-reportgenerator-globaltool`）。
- 指令以 Windows PowerShell 5.1 或 PowerShell 7 執行。使用 Claude／Codex 工作流程時，另準備對應 CLI；容器測試另需 Docker。

平台選單不會修改 `global.json` 或專案設定。只有 `coverlet.MTP` 的專案不能直接使用預設 Microsoft Code Coverage 指令。

## 取得、安裝與升級

從 [v0.8.3 Release](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.8.3) 下載 `dotnet-testing-agent-0.8.3.vsix`。

1. 開啟 Extensions 面板（`Ctrl+Shift+X`）。
2. 點選右上角 `...` → **Install from VSIX...**，選擇套件。
3. 完整結束並重新開啟 VS Code。
4. 查看工具包版本資訊，確認版本為 v0.8.3。

命令列安裝：

```powershell
code --install-extension dotnet-testing-agent-0.8.3.vsix --force
```

升級 Extension 不會自動更新或解除工作區的測試工作流程，不需要先移除模式或刪除 manifest。

## Code Coverage 使用方式

1. 開啟目標工作區，從工具包展開「Code Coverage」；多根目錄工作區先選擇此次使用的根目錄。
2. 選擇 `.sln` 或 `.slnx`，再選擇測試 `.csproj`；「不指定專案」使用整個所選方案。
3. 確認 VSTest／MTP 平台與 MTP 指令模式，查看工具與設定前置條件，確認實際 SDK、runner、所有目標專案及工具相容。
4. 複製 Coverage command，在 PowerShell 的所選工作區根目錄執行，確認測試及 Cobertura 結果產生。
5. 複製同組 HTML Report command，在同一根目錄執行；HTML 輸出位於該組的 `coverage/<範圍>/<執行識別>/html`。

同一工作區可包含使用不同 runner 的方案。面板使用方案目錄往上至工作區根目錄最近的 `global.json`；Coverage 指令必要時會暫時切換到該設定目錄，執行後恢復原目錄。兩段指令都從工作區根目錄執行，無須另開工作區或修改根目錄設定。

兩段指令使用同一組結果目錄。複製或面板重繪不會更換該組；重新掃描或變更選擇會換新組，必須重新執行 Coverage。重複執行舊組可能混入先前結果，Extension 不刪除舊檔案。

Coverage 掃描會採用適用的 `VersionOverride`，中央 MTP 版本需配合直接參照。直接 `xunit.v3.mtp-v2` 可作為測試／MTP 證據，但不把 xUnit 套件版本當成 MTP 精確版本；明確 `IsTestProject=false` 仍排除，MTP 版本證據衝突無法經確認略過。

混合平台方案或覆蓋率套件未在本版可讀設定找到直接參照時，請改選符合條件的測試專案。錯誤設定須修正後重新掃描。沒有方案時不產生猜測目標的指令。包含無法安全表示的報告搜尋特殊字元之工作區路徑，會停用複製並顯示原因。

本版僅依工作區內可直接解析的專案、props、targets 與 Import 辨識，不解析 SDK 內部、傳遞套件或工作區外上層設定。套件證據 `no` 表示未在可讀設定找到直接參照，會停用指令，並不表示已確認實際環境缺少套件；`unknown` 須由使用者確認實際環境，已知衝突仍不可略過。無不確定設定且沒有已辨識測試證據的 `Microsoft.NET.Sdk` 專案不列入清單；若測試設定僅由未解析來源提供，可能無法列出或產生指令。`MSTest.Sdk` 可辨識為測試專案，套件仍可能未確認。

## 預設提示詞使用方式

1. 在工具包展開 Claude 或 Codex 模式，選擇目前要使用的 Full／Lite，再開啟「預設提示詞」分頁。
2. Full 提供 Unit、Integration、Aspire、TUnit；Lite 提供 Unit。Unit 預設展開，其餘收合，可自行展開查看；收合時也能按「複製提示詞」。
3. 成功後顯示「已複製」。貼到對應的 Claude Code／Codex，替換待填欄位，再自行送出；Claude 使用 `/`，Codex 使用 `$`。複製只取得公版，不會啟動工作流程或執行測試。
4. 「被測試專案」與「測試專案」都填入包含 `.csproj` 檔名、以目前工作區根目錄為基準的相對路徑。可展開「路徑填寫說明與範例」確認；多根目錄工作區以該專案所在根目錄為基準。

例如：

```plaintext
被測試專案：src/MyApp/MyApp.csproj
測試專案：tests/MyApp.Tests/MyApp.Tests.csproj
```

查看與複製公版可離線使用，也可自行選取提示詞文字手動複製。執行工作流程前仍需準備對應 CLI、初始化所選模式，並依工作流程填妥欄位。

## 更新後確認

- Code Coverage 以獨立區塊顯示，預設收合；未安裝工作流程模式也能掃描。
- 方案及測試專案路徑正確，兩段指令可分別複製並顯示「已複製」。
- 複製操作不會執行測試、建立終端機、安裝工具或修改專案。
- Claude／Codex 的「預設提示詞」分頁依 Full／Lite 顯示正確清單，複製內容保留換行、待填欄位及 `.csproj` 路徑基準說明。
- 既有 Claude／Codex 模式與自訂檔案保留；需要檢查工作流程時可在各模式執行環境診斷。
