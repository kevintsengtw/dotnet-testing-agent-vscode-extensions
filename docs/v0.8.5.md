# dotnet Testing Agent v0.8.5 安裝指南

此版補足交易失敗後的警告呈現與人工處理指引，並納入已合併的工具鏈、封裝與公開文件維護。

## 前置需求

- VS Code 1.85 以上、Node.js 18 以上。
- 使用 Claude／Codex 工作流程時，準備對應 CLI 與適用的 .NET SDK；需要容器的工作流程另需 Docker。
- Code Coverage 指令以 PowerShell 執行；SDK、runner、覆蓋率套件與 ReportGenerator 需求見 [v0.8.3 安裝指南](v0.8.3.md)。macOS 執行這些指令另需 PowerShell 7。

## 取得、安裝與升級

從 [v0.8.5 Release](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.8.5) 下載 `dotnet-testing-agent-0.8.5.vsix`，複製到目標電腦後依下列步驟安裝。

1. 先備份原工作區，保留 `.agents`、`.claude`、`.codex` 與 `.dotnet-testing-agent` 的內容。
2. 開啟 VS Code Extensions 面板；Windows 快捷鍵為 `Ctrl+Shift+X`，macOS 為 `Command+Shift+X`。
3. 點選右上角 `...` → **Install from VSIX...**，選擇 `dotnet-testing-agent-0.8.5.vsix`。
4. 完整結束並重新開啟 VS Code。
5. 查看工具包版本資訊，確認 Extension 版本為 v0.8.5；保留既有模式，逐一執行環境診斷。

若已設定 VS Code 的 `code` 命令，可在 VSIX 所在目錄執行：

```sh
code --install-extension ./dotnet-testing-agent-0.8.5.vsix --force
```

一般升級不需要先移除 Extension。更新 Extension 不會自動重新部署或解除安裝工作區模式，也不需要為了取得本次警告與指引而重新安裝所有 Skills／Agents。

## 本版變更

- 部署或 Codex Agent 設定失敗後，輸出逐筆列出交易回復警告碼與路徑。即使原有內容已復原，仍有 discard 或備份時，通知也會提示人工檢查。
- 環境診斷的交易殘留提醒補上核對條件與處理順序；無法確認已復原或資料歸屬時，保留資料並停止處理。交易、清理及殘留掃描邏輯維持原狀，沒有新增自動清理。
- 納入已合併的 Node.js 20 工具鏈、CI 與封裝維護。這不改變使用者端 Node.js 18 以上的前置需求。
- 六套 Samples 與操作指南已獨立公開，維持從[公開儲存庫](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions)以 Git clone 或 **Code → Download ZIP** 取得；範例不包含在 VSIX 中，操作入口為 `samples/README.md`。

Claude Lite 共存／衝突修正已包含於 v0.8.4，不是本版的新修正。2026-10-19 已在 Windows 的隔離 VS Code 環境完成四模式乾淨安裝，以及由正式 v0.8.4 升級至 v0.8.5 的安裝與診斷檢查。四模式均無診斷錯誤，Claude Full 僅保留既有用量統計範圍提醒；升級前後的 423 份工作區檔案內容與修改時間不變，包含三份自訂 Skills。此輪未執行 AI 或 .NET 測試工作流程，也未重新驗證 macOS；v0.8.4 的 Windows／macOS 歷史紀錄保留在 [原安裝指南](v0.8.4.md)。

## 交易回復後的人工處理

環境診斷若列出 `TRANSACTION_RECOVERY_REQUIRED` 或 `TRANSACTION_DISCARD_CLEANUP_REQUIRED`，請先保留資料。備份目錄位於工作區上一層，名稱形如 `.dta-workflow-backup-<識別碼>`；discard 位於原 target 旁，名稱形如 `<原檔名>.dta-discard-<識別碼>`，可能保留失敗操作寫入的內容。

1. 暫停該工作區的安裝、更新、修復及 Agent 設定操作，保留環境診斷報告與「輸出 → dotnet-testing-agent」的操作結果及路徑。
2. 另存目前檔案、指定 discard 與備份目錄。開啟備份內的 `transaction.json`，核對 `workspaceRoot`、entries 的 `relativePath`、`backup`、`discard` 與實際檔案；不要修改 journal，也不要只憑 `rolled-back` 或檔案存在就認定已復原。
3. 依操作前備份、版本控制及實際內容，確認受影響檔案均已正確復原，或原本不存在的項目已回復為不存在，且不再需要交易復原資料。仍有失敗、缺檔、內容不符、journal 無法解讀或歸屬不明時，保留全部資料並停止處理。
4. 確認後先保留 discard 中需要的內容，再人工移除已核對屬於該筆交易的 discard；若已不存在，繼續核對對應備份。只處理已核對的精確路徑，不依名稱批次刪除。
5. 確認該筆 discard 已處理且不再需要復原資料後，才人工移除對應的整個備份目錄（含 `transaction.json`）。只移除 discard 仍可能留下備份提醒；先刪備份可能讓診斷失去尋找 discard 的紀錄。
6. 重新執行環境診斷，確認該筆提醒已消失；其他提醒須依各自路徑逐筆核對，不將其他交易或使用者檔案一併清理。

## 更新後確認

- 版本資訊顯示 v0.8.5，四模式的安裝狀態與來源版本仍符合原工作區紀錄。
- 對實際使用的 Claude／Codex 模式重新執行環境診斷；若已有交易殘留，依本指南核對，不需刻意製造操作失敗。
- 原有自訂 Skills、Agent 模型設定與使用者檔案保留。Claude Full 既有的用量統計範圍提醒仍依報告說明處理。
- Code Coverage 與預設提示詞仍可查看及複製；複製不會自動執行測試工作流程。
