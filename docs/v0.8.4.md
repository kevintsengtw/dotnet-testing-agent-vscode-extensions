# dotnet Testing Agent v0.8.4 安裝指南

此版修正既有 Skill 共存與衝突判定，支援保留既有 Full、直接安裝 Lite。2026-10-16 已完成 Windows 實際面板安裝與環境診斷驗證；使用者也確認 macOS R2 安裝成功，安裝後環境診斷畫面正常。

## 內建離線版本

| 內容 | 來源版本 |

內建來源沿用 v0.8.3，保留 Code Coverage 與預設提示詞功能。工作流程的來源版本與 Extension 版本分開管理。

## 前置需求

- VS Code 1.85 以上、Node.js 18 以上。
- 使用 Claude／Codex 工作流程時，準備對應 CLI 與適用的 .NET SDK；需要容器的工作流程另需 Docker。
- Code Coverage 產生的指令以 PowerShell 執行；其 SDK、runner、覆蓋率套件與 ReportGenerator 需求沿用 [v0.8.3 安裝指南](v0.8.3.md)。在 macOS 執行這些指令需另備 PowerShell 7。

## 取得、安裝與升級

從 [v0.8.4 Release](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.8.4) 取得 `dotnet-testing-agent-0.8.4.vsix`，複製到目標電腦。

1. 先備份原工作區，保留 `.agents`、`.claude`、`.codex` 與 `.dotnet-testing-agent` 的內容。
2. 開啟 VS Code Extensions 面板；Windows 快捷鍵為 `Ctrl+Shift+X`，macOS 為 `Command+Shift+X`。
3. 點選右上角 `...` → **Install from VSIX...**，選擇 `dotnet-testing-agent-0.8.4.vsix`。
4. 完整結束並重新開啟 VS Code。
5. 查看工具包版本資訊，確認 Extension 版本為 v0.8.4。若先前已安裝第一份 v0.8.4 候選，請以本次提供的新 VSIX 覆蓋安裝；版本號相同，可用下列 `--force` 指令。

若已設定 VS Code 的 `code` 命令，可在 VSIX 所在目錄執行：

```sh
code --install-extension ./dotnet-testing-agent-0.8.4.vsix --force
```

一般升級不需要先移除 Extension，也不會自動更新或解除安裝工作區的測試工作流程。

## 本版修正

- 同一路徑、相同內容的既有 Skills 可供多個模式沿用，不再只因記錄的模式來源版本不同而誤報 `MIXED_VERSION_CONFLICT`。
- Claude Full v1.7.3 與 Lite v1.2.0 的 `dotnet-test/SKILL.md` 若符合已核對的相容內容、實際檔案與紀錄雜湊一致，且有已驗證的使用紀錄，可沿用既有正式原檔。沿用不會取得覆寫或刪除權限，也不會將未知檔案自動接管。
- 未知來源、無有效使用紀錄或使用者修改仍會停止安裝，顯示 `UNMANAGED_CONFLICT` 與具體路徑。
- 前置檢查失敗不會寫入檔案；安裝通知會保留具體衝突說明，方便從「輸出 → dotnet-testing-agent」查閱路徑。
- 原本由 Extension 管理的同路徑 Skills，仍依最後明確安裝、更新或修復模式的固定來源內容部署，保留其他模式的使用紀錄。

## 保留既有 Full，直接安裝 Lite

既有 Full 的 `.claude/skills/dotnet-test/SKILL.md` 若為未接管狀態（`createdByExtension: false`），v0.8.4 可在通過上述核對後直接沿用。不需要先解除安裝 Full、移走 Skill 或修改 manifest。

Claude Full v1.7.3 與 Lite v1.2.0 的 `dotnet-test/SKILL.md` 差異為建置警告的輸出方式，三個參考檔案內容相同。沿用 Full 原檔時仍顯示建置警告；安裝通知與環境診斷會說明來源差異，Lite 的原始來源證據及實際使用雜湊分別保留。此相容例外不會自動套用至其他 Skills 或未來版本。

驗證步驟：

1. 安裝本次 VSIX 並完整重啟 VS Code，保留原有工作區。
2. 在 DTA 的 Claude 模式面板，直接安裝 **Claude Lite**。
3. 確認 Full 與 Lite 均為已安裝，通知說明沿用既有正式來源 Skill。
4. 對兩個 Claude 模式執行環境診斷，確認沒有檔案衝突；沿用來源差異會以資訊項目列出。
5. 確認原有 Codex 模式與自訂檔案仍在。

若仍出現 `UNMANAGED_CONFLICT`，先保留原檔並查看輸出的具體路徑；可能是未知來源、來源證據不足或已有自訂內容，請勿直接刪除檔案或修改管理紀錄以略過檢查。

## 已確認的安裝情境與範圍

macOS 已回報的結果為：保留既有 Full、直接安裝 Lite 成功；Lite 使用線上正式來源 `v1.2.0`（`88c3528ee35b`），安裝後畫面顯示環境正常。部署紀錄保留四模式，既有 `dotnet-test` 仍為未接管狀態，由 Full 與 Lite 共用，兩個模式各自保留原始來源證據。

若先前複製過 `not-installed` 報告，請在安裝完成後重新執行環境診斷再複製。舊報告沒有時間戳，無法用它判定目前狀態。本次 macOS 驗證限於安裝、部署紀錄及環境診斷畫面，未執行 .NET 測試工作流程。

Windows 11 使用 VS Code 1.142.0、Node.js 26.12.0、Claude Code 2.1.263 與 Codex CLI 0.162.1，已透過面板完成四模式乾淨安裝，以及既有 Full／Codex 工作區直接加裝 Lite。原有 410 個檔案保持不變，Full 的 `dotnet-test` 原檔與未接管狀態保留，Lite 安裝後診斷正常。

Full 與 Lite 共存後，四模式診斷沒有錯誤；Claude Full 仍會顯示既有的用量統計範圍提醒，因其用量可能包含 Lite Agent，不應將該數字視為只屬於 Full。Lite、Codex Full 與 Codex Lite 的診斷正常。Windows 本次亦未執行 .NET 測試工作流程。

## 更新後確認

- 版本資訊顯示 v0.8.4，原有模式的安裝狀態與來源版本符合工作區紀錄。
- 相同內容的既有參考檔案不再被列為版本衝突；已核對相容的 `dotnet-test` 原檔可沿用，未接管狀態保持不變。
- 直接安裝 Lite 後，Claude Full 與 Lite 可同時安裝，環境診斷沒有檔案衝突；若有提醒，依報告內容確認。
- 原有 Codex Full／Lite、自訂 Skills 與設定保留。
- Code Coverage 及預設提示詞面板仍可使用；複製指令或提示詞不會自動執行工作流程。
