# dotnet Testing Agent v0.8.2 安裝指南

此版修正舊版移轉工作區解除安裝 Full 模式後，中央部署 manifest 被誤判為無效，造成後續管理或重新安裝失敗的問題，並改善 Codex Agents 的排列與連續設定操作。

## 本版重點

- Codex Full 的 Agents 區塊依常用順序排列為 Unit、Integration、Aspire、TUnit；Codex Lite 維持兩個 Unit Agents。
- Full／Lite 套用或重設模型與推理強度後，保留目前捲動位置與已展開的 Agent 技術資訊，方便接續調整其他 Agent。
- Claude Full／Codex Full 解除安裝後，保留的歷史移轉紀錄不再被當成目前已安裝模式。
- Codex Full／Lite 可接續解除安裝、重新安裝及執行環境診斷。
- 已受此問題影響的 manifest 可由修正版直接讀取，不需要手動刪除或修改工作區中的 `.dotnet-testing-agent/manifest-deployment.json`。
- 目前安裝狀態、檔案歸屬與來源完整性仍會驗證；其他模式仍使用的檔案及使用者自訂內容保留。

## 前置需求

- VS Code 1.85 以上、Node.js 18 以上。
- 依使用模式準備 Claude Code 或 Codex；容器測試另需 Docker。

## 取得套件

從 [v0.8.2 Release](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.8.2) 下載 `dotnet-testing-agent-0.8.2.vsix`。

## 安裝或升級

1. 開啟 Extensions 面板（`Ctrl+Shift+X`）。
2. 點選右上角 `...` → **Install from VSIX...**。
3. 選擇 `dotnet-testing-agent-0.8.2.vsix`。
4. 完整結束並重新開啟 VS Code。
5. 開啟原工作區，確認工具包版本資訊為 v0.8.2。

命令列安裝：

```powershell
code --install-extension dotnet-testing-agent-0.8.2.vsix --force
```

安裝新版 Extension 不會自動更新或解除工作區中的測試工作流程。不需要先解除 Extension 或手動重建中央 manifest。工作流程版本的升級仍由各模式的「升級安裝」操作處理。

若已安裝 v0.8.2 候選版，命令列使用 `--force` 取代同版本套件。GUI 安裝時依提示確認取代，再完整重啟 VS Code。

## 更新後確認

1. 查看 Codex Full／Lite 的已安裝狀態，並執行環境診斷。
2. 如需重新安裝，在各模式的管理入口選擇解除安裝；確認另一模式及 Claude 模式仍保持其原有狀態。
3. 分別重新安裝 Codex Full／Lite，再執行環境診斷；不應再因已解除模式的歷史紀錄出現 `DEPLOYMENT_OWNERSHIP_MANIFEST_INVALID`。
4. 確認自訂 Skills、檔案與既有 Codex 設定值仍保留；原有 Agent 模型設定可在 Agents 頁面檢視。
5. Codex Full 的 Agents 應依 Unit、Integration、Aspire、TUnit 排列；套用或重設後，確認目前位置與已展開的 Agent 技術資訊保留。

若出現其他設定或檔案衝突，請保留環境診斷報告及記錄供檢查；不要直接刪除中央 manifest。
