# dotnet Testing Agent v0.8.1 安裝指南

預設離線安裝採用下表列出的四模式正式版本。「版本資訊」會列出各模式的內建離線版本；「查看 Release」可隨時開啟所選模式的官方最新發行頁，不受是否已安裝或 GitHub API 查詢額度限制影響。

同一路徑的受管理 Skill 只保留一份，安裝、更新或修復時採用最後部署模式的原始來源內容。不同 Skills 根目錄中的同名 Skill 各自保留；解除安裝其中一個模式時，其他模式仍使用的檔案會保留。

v0.8.1 支援新版正式工作流程來源、更新共用 Skills，並擴充 Codex Full／Lite 逐 Agent 的模型選項。四個模式的技術 Skills 共用，各模式內容依來源管理。Claude Full／Lite 共用路徑中的 Skills 採用最後部署的版本。切換側邊欄中的查看模式不會修改工作區。

Codex Full `v1.3.1` 的正式來源使用 16 個 Agent、5 個模式專屬 Skills 與 30 個共用 Skills。59 個 runtime scripts 與 5 份 manifest 位於 `.codex/scripts/dotnet-testing-codex-full/`；四套流程各自提供實際用量 HTML 與選用 Standard credit 換算，並在派遣前進行 NuGet 預檢。來源 Agent 維持 `gpt-5.6-sol`／`medium`，既有 Extension 模型選擇與使用者設定會保留。升級只移除原先記錄為 Extension 管理的舊 scripts；不部署封存檔中殘留的舊估算器。

線上初始化與更新支援 Codex Lite `v1.2.2`：用量儀表板加入 GPT-6.1 Sol Standard credit 費率，工作流程在派遣 Agent 前建立結果交付與停止回報目錄。v1.2.1 已有的 NuGet 預檢仍依還原診斷提供處理建議，一般啟動不需要 `NUGET_PACKAGES` 或為 NuGet 修改 `.codex/config.toml`。還原失敗時會在建立 run 及派遣 Agent 前停止；升級保留既有使用者設定與模型選擇。

## 下載

從 [v0.8.1 Release](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.8.1) 下載：

- `dotnet-testing-agent-0.8.1.vsix`

## 安裝或升級

1. 開啟 Extensions 面板（`Ctrl+Shift+X`）。
2. 點選右上角 `...` → **Install from VSIX...**。
3. 選擇 `dotnet-testing-agent-0.8.1.vsix`。
4. 完整結束並重新開啟 VS Code；不要只執行 Reload Window。

命令列安裝：

```bash
code --install-extension dotnet-testing-agent-0.8.1.vsix
```

### 從 v0.8.0 升級

- 四個已安裝模式會保留各自的來源紀錄；安裝新版 Extension 不會自動更新工作區。
- 選擇要升級的 Full 或 Lite 模式，再按「升級安裝」。Extension 依已安裝、內建及可取得的線上版本，選出已確認的較新版本；確認目標版本與來源後直接升級，不必先解除安裝。升級會保留使用者檔案與 Agent 設定，失敗時復原原有內容。
- 更新完成後可繼續管理其他模式，不需要先關閉新版通知。手動版本查詢不會因背景查詢尚未結束而誤判失敗。
- GitHub 限制版本查詢時會顯示可重試時間；四模式與 Shared Skills 共用等待時間，安裝不重複查詢仍有效的固定來源。逾時、連線失敗與來源驗證失敗分別顯示原因。查詢受限或連線失敗時，仍可升級至較新的完整內建版本，拒絕降版；尚未安裝時可直接安裝內建版本。
- 每個模式保留一個管理入口，依版本提供升級安裝、修復或解除安裝。已是內建最新版但無法查詢線上版本時，會顯示「已是內建最新版本；線上最新版本尚未確認」。
- 可先執行環境診斷，再依各模式面板的更新提示逐一更新。尚未更新的正式舊版不會僅因新版 Extension 使用較新的共用 Skills 而被判為檔案修改。
- 需要時可修復或解除安裝個別模式。修復沿用該模式的固定來源；bundled 模式原始內容未變時，共用 Skills 會隨修復交易採用新版內建版本。解除安裝會保留其他模式仍使用的共用檔案。

### 從 v0.7.0 升級

- 開啟實際使用的 Claude 或 Codex 面板，查看 Full 的來源與安裝狀態。
- 依面板提供的操作執行更新或重新初始化，再執行環境診斷。
- v0.7.0 Codex Full 的正式 managed assets 會先通過 exact-source reconciliation；若檔案已被使用者修改或來源證據不符，操作會停止而不覆寫。
- Lite 不會自動安裝；需要時再個別安裝 Claude Lite 或 Codex Lite。
- Shared Skills 會隨已授權的模式安裝／更新交易升級至內建 v2.4.5，未知的自訂 Skills 仍會保留。v2.4.5 更新 Web API／Aspire 測試範本與 TUnit、FakeTimeProvider 等說明。Web API 範本的 `IntegrationTestBase` 移除 `ResetTime()`；重新複製範本且原測試有呼叫此方法時，請改用 `AdvanceTime()` 往前推進或依目前時間計算。

## 本版重點

- 四個模式各自記錄安裝狀態、更新與解除安裝；Skills 維持上游原有名稱與目錄。
- scripts 依所選工作流程的固定來源更新；離線安裝沿用內建來源配置，保留自訂檔案。
- 目前查看的 Full／Lite 按鍵使用實心樣式及「✓ 目前」；每個模式是否已安裝另行顯示，不必靠顏色猜測。
- Codex Agents 分頁在每張 Agent 卡片直接顯示資產狀態、來源預設、目前模型、模型與推理強度下拉選單。
- Codex 設定在套用前執行唯讀安全檢查，再原子更新指定 Agent；可以只套用或重設一個 Agent。
- Codex Lite v1.2.2 支援 GPT-6.1 Sol Standard credit 換算，並在派遣前準備 Agent 的結果交付與停止回報目錄；v1.2.1 的 NuGet 預檢行為維持不變。
- 每次部署使用固定 stable tag 與 exact commit，並在同一交易內完成寫入與 rollback；不會以 moving `latest` 或部分 online／bundled 混合內容更新工作區。
- Doctor 可診斷 managed hash drift、缺檔、混合版本、來源衝突、legacy shared path、Codex override metadata 與使用者設定問題。
- 修正模式診斷遺漏共用環境結果的問題；Node.js 或 CLI 缺失會顯示於各模式畫面及複製的完整報告。
- Shared Skills 和四個工作流程來源的更新通知提供「查看 Release」、「稍後」與「忽略此版本」；Shared Skills 不會被通知機制靜默更新。

## Codex Agent 模型設定

套用或重設 Agent 的模型與推理強度後，會保留目前的 Agents 頁籤與查看模式，自動環境診斷不再跳回總覽。

既有 v0.8.0 模式的原始內容未變時，升級 Extension 後仍可設定模型，不必先更新工作流程。原始內容的取得問題會顯示具體原因；執行環境診斷不會改寫 Agent 設定。

模型選單依序如下；未自訂 Agent 的選單仍預選 GPT-6 Sol：

- GPT-6.1 Sol
- GPT-6 Astra
- GPT-6 Sol
- GPT-6 Luna
- GPT-5.6 Sol
- GPT-5.6 Terra
- GPT-5.6 Luna

支援推理強度：Low、Medium、High、XHigh、Max。

![Codex Lite 的 Agent 資產狀態與模型設定集中在同一卡片](https://raw.githubusercontent.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/main/images/v0.8.0-codex-lite-agent-settings.png)

每張 Agent 卡片會同時顯示資產是否存在、來源預設、目前 model／effort、兩個下拉選單，以及單一 Agent 的套用／重設。受管理路徑與 exact source 位於預設收合的「Agent 技術資訊」。Codex Full 的 16 個 Agents 依 Aspire、Integration、TUnit、Unit 分組；Codex Lite 顯示兩個 Unit Agents。

### 套用 model／effort

1. 在指定 Agent 卡片選擇模型與推理強度。
2. 點選「套用」。Extension 會先唯讀檢查設定與受管理檔案，確認沒有衝突後原子寫入。
3. 套用成功後執行 **Developer: Reload Window**。
4. Reload 完成後建立新的 Codex task；已在執行中的 task 不會重新載入設定。

若要回復來源預設，請對指定 Agent 使用「重設」。Full 與 Lite 的設定與重設範圍互相隔離。

![Codex Full 的 Unit Agents 分組與逐 Agent 設定](https://raw.githubusercontent.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/main/images/v0.8.0-codex-full-unit-agents.png)

## 更新通知

Extension 會在啟動及完成安裝／更新操作後，檢查 Shared Skills、Claude Full、Claude Lite、Codex Full、Codex Lite 的最新 stable Release。通知提供：

- **查看 Release**：開啟對應的 allowlisted Release 頁面；Shared Skills 不會因此進入部署流程。
- **稍後**：本次不處理，不記錄忽略狀態。
- **忽略此版本**：只忽略指定來源、repository 與 stable tag；後續新版本仍會再次通知。

通知不會靜默更新工作區。真正的安裝或更新仍必須由使用者明確操作，並經過完整 preflight、integrity 與 transaction 檢查。

## 更新後確認

- 從 Activity Bar 開啟「dotnet-testing-agent 工具包」。
- 確認需要的 Full／Lite 模式顯示「已安裝」，目前查看的模式另有「✓ 目前」。
- 對每個實際使用的模式執行「環境診斷」。
- Claude Full v1.7.3 與 Lite 共存時，可能顯示「Full 用量統計可能包含 Lite Agent」。這是上游用量統計的範圍限制，不阻擋使用，也不需要修復；同一工作階段中的 Full 報表可能包含 Lite Agent 用量。
- 版本資訊應顯示內建 Shared Skills `v2.4.5`、Claude Full `v1.7.3`、Claude Lite `v1.2.0`、Codex Full `v1.3.1`、Codex Lite `v1.2.2`；工作區已安裝版本另行顯示。
- 若調整 Codex Agent 模型，套用後執行 Reload Window，再以新 task 驗證設定。
- 完整重啟 Claude Code 或 Codex，再執行所需的 Unit、TUnit、Integration 或 Aspire 工作流程。
