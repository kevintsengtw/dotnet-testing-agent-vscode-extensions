# dotnet Testing Agent v0.7.0-beta.5 安裝指南

> 這是 **prerelease**，用於發佈前的工作流程驗證，不是正式版。正式版請使用 [v0.6.0](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.6.0)。
>
> 本版移除 GitHub Copilot 模式，只支援 Claude Code 與 Codex。

## 本版重點

以 beta.4 對四種測試工作流程（Unit、TUnit、Integration、Aspire）× 兩個模式共八種組合進行實機驗證，全部功能通過。本版納入驗證過程中發現的修正。

**Claude 的 TUnit 與 Aspire 不再可能跳過品質審查。**

這兩種工作流程先前在「測試首次全數通過」時可能直接結束，不執行第四階段的品質審查。實測顯示這個行為不穩定——條件完全相同的兩次執行，一次跳過、一次沒跳過。

測試通過不等於測試寫得好。品質審查檢查的是命名是否精確、斷言是否到位、測試場景有無遺漏，這些問題都不會讓測試執行失敗。同批驗證中，有執行審查的工作流程抓到了「測試名稱宣稱涵蓋兩種情境、實際只測了一種」與「容器映像未固定版本會造成飄移」等問題。本版起四種工作流程一律執行審查。

**Codex 的審查裁決不再可能缺漏。**

Reviewer 完成審查後需要留下一個正式裁決欄位，但只有在使用者主動提供測試情境時，說明文件才交代這個欄位該怎麼判定。沒有提供情境時，Reviewer 缺乏依據——四種工作流程實測有兩種沒有寫入。本版補上判定規則，並明訂不得因為缺少情境或測試全過就直接填「通過」。

**Codex 的 token 用量估算修正。**

先前把同一份檔案重複計算了兩次，估算值偏高。修正後每份寫出的檔案只計一次。**新舊數值不可直接比較**——估算格式版本已更新。

另外，暫存目錄的清理行為在四種工作流程間已一致化，並改用在 Windows 上更可靠的方式執行。

## 下載

從 [v0.7.0-beta.5 Release](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.7.0-beta.5) 下載：

- `dotnet-testing-agent-0.7.0-beta.5.vsix`

## 安裝或升級

1. 開啟 Extensions 面板（`Ctrl+Shift+X`）。
2. 點選右上角 `...` → **Install from VSIX...**。
3. 選擇 `dotnet-testing-agent-0.7.0-beta.5.vsix`。
4. 完整結束並重新開啟 VS Code；不要只執行 Reload Window。

命令列安裝：

```bash
code --install-extension dotnet-testing-agent-0.7.0-beta.5.vsix
```

**從 v0.7.0-beta.4 升級**：本版**兩個模式的工作流程內容都有變更**。安裝後請分別開啟 **Claude 模式**與 **Codex 模式**面板，各執行一次「更新／修復」，讓工作區取得修正後的內容。

更新完成後，版本資訊面板的「Claude 工作流程」應顯示 `beta/agent-modes (42265641)`、「Codex 工作流程」應顯示 `beta/agent-modes (b8b36b97)`，兩列狀態皆為「✓ 已套用」。

**從 v0.6.0 升級前請注意**：本版變更了共用 Skills 的安裝位置，且移除 Copilot 模式。建議先在非正式的工作區驗證，確認四種測試工作流程可正常運作後，再套用到日常使用的專案。

## 更新後確認

- 從 Activity Bar 開啟「dotnet-testing-agent 工具包」。
- 「測試工作流程內容」四列應皆顯示「✓ 已套用」。
- 對使用中的模式執行**環境診斷**，其結論應與面板顯示一致。
