# dotnet Testing Agent v0.8.6 安裝指南

此版更新 Codex Lite 內建來源、Codex Agent 模型選單，並修正部署前置檢查、交易回復與診斷。

## 內建離線版本

| 內容 | 來源版本 |
| --- | --- |
| Shared Skills | `v2.4.5` |
| unit-test-scenarios | `d0050198` 精確 commit |
| Claude Full | `v1.7.3` |
| Claude Lite | `v1.2.0` |
| Codex Full | `v1.3.1` |
| Codex Lite | `v1.2.4`，固定 `e720870d88cd559c1c5b0eb66946ddde5ee3ad26` |

本版不包含 Codex Full v1.3.2。四模式及上游原有 Skills 名稱、目錄結構保留；工作流程版本與 Extension 版本分開管理。

## 前置需求

- VS Code 1.85 以上、Node.js 18 以上。
- 使用 Claude／Codex 工作流程時，準備對應 CLI 與適用的 .NET SDK；需要容器的工作流程另需 Docker。
- Code Coverage 的 PowerShell、runner 與 ReportGenerator 需求沿用 [v0.8.3 安裝指南](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/blob/main/docs/v0.8.3.md)。macOS 執行 Coverage 指令另需 PowerShell 7。

## 安裝與升級

從 [v0.8.6 Release](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/releases/tag/v0.8.6) 下載 `dotnet-testing-agent-0.8.6.vsix`，再依下列步驟安裝。

1. 備份工作區，保留 `.agents`、`.claude`、`.codex` 與 `.dotnet-testing-agent` 的內容。
2. 開啟 VS Code Extensions 面板（Windows：`Ctrl+Shift+X`；macOS：`Command+Shift+X`），選擇 `...` → **Install from VSIX...**，選取取得的 `dotnet-testing-agent-0.8.6.vsix`。
3. 完整結束並重新開啟 VS Code，確認工具包版本資訊顯示 v0.8.6。
4. 保留既有模式，先對實際使用的 Claude／Codex 模式執行環境診斷，確認來源、檔案與使用者設定。
5. 若要取得內建的 Lite v1.2.4，另在 Codex Lite 模式執行更新；只更新 Extension 不會自動重新部署工作區來源。

已設定 `code` 命令時，也可在 VSIX 所在目錄執行：

```sh
code --install-extension ./dotnet-testing-agent-0.8.6.vsix --force
```

一般升級不需要先移除 Extension 或所有 Skills／Agents。若更新遇到使用者修改或來源衝突，先保留檔案與診斷報告，不要以整目錄覆寫排除衝突。

## 本版變更

- Codex Lite 內建來源更新至 v1.2.4，包含交接身分與完成紀錄、情境與測試對應、repair 報告及 NuGet 診斷調整。
- Lite 的 token-usage HTML report 新增 `gpt-6.1-terra` credit 試算；依上游保存的 Standard 費率估計，不代表實際扣款，未知模型不套用其他模型費率。
- Codex Full／Lite 的 Agent 模型選單加入 `gpt-6.1-terra`；前三項為 `gpt-6-astra`、`gpt-6.1-sol`、`gpt-6.1-terra`。沒有已保存選擇時，選單預設為 `gpt-6.1-sol`；明確保存的選擇維持原值。這不改寫上游 Agent 的來源預設。
- 納入交易回復、discard 檢查、部署預檢與診斷修正，並重用 journal 的固定相對路徑，減少重複計算。原格式、寫入頻率及回復安全檢查保留，沒有新增自動清理。
- 納入 fast-uri 3.1.9 與 serialize-javascript 7.1.4 相依修補。

## 更新後確認

- 確認 Extension 顯示 v0.8.6；來源版本以工作區的實際安裝紀錄為準，不要求其他模式隨 Lite 更新而重新安裝。
- 若已更新 Codex Lite，確認其來源為 v1.2.4，執行環境診斷並核對原有設定、自訂檔案及其他模式仍在。
- 在 Agent 設定檢查模型選單與既有選擇；只有明確套用設定才變更 Agent 檔案。
- 若有 `TRANSACTION_RECOVERY_REQUIRED` 或 `TRANSACTION_DISCARD_CLEANUP_REQUIRED`，保留資料，依 [v0.8.5 人工處理指引](https://github.com/kevintsengtw/dotnet-testing-agent-vscode-extensions/blob/main/docs/v0.8.5.md#交易回復後的人工處理)核對指定交易，不依檔名批次刪除。

Extension 的安裝與診斷檢查不代表上游 AI／.NET 工作流程已執行；相關 CLI、模型及執行情境仍須依各工作流程的條件確認。
